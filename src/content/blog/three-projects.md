Aurum 是 Go，InkFlow 是 Java 17，Learning Studio 是 Java 21。语言不一样，领域也毫不相干——记账、内容生产、学习。但把三个仓库摆在一起看，骨架是同一副。

## 设计文档是唯一权威

三个项目都有「先改文档再改代码」的规矩。Aurum 的 `docs/design.md` 写了全部定稿决议：私密账不做、流水软删、管理台和前台强制分离。Learning Studio 的设计文档把认知状态的不变式（只升不降、乐观锁）写成条款。InkFlow 把「发布环节永久人工」这种红线记在 README 第一条。

不写文档的副作用我很清楚：三个月后自己看代码，分不清「当初有意如此」和「随便写的」。文档解决的是和自己的记忆打架的问题。

## .env + 云库，本地零依赖

三个项目都不在本地起数据库：云 MySQL 一个库，`.env` 存连接，`.env.example` 进仓库做模板，`.env` 本身 gitignore。换台机器开发，装完依赖填个 `.env` 就能跑。

## 禁止参数兜底

漏传参数必须抛明确异常并修调用源头，禁止底层用默认值悄悄掩盖。这条看起来较真，但防的是最难查的那种 bug：系统没崩，只是 quietly 做错了事。

## 禁止循环内逐条 SQL

INSERT/UPDATE/SELECT 一律批量：内存里组装好，一次写/查。三个项目都定死在规则里，不然总会以「先跑起来再说」开头、以 N+1 收尾。

## AI 只管生成，不管兜底

DeepSeek 的输出必须过严格校验，缺字段、超范围直接失败，不做静默兜底。InkFlow 的 AI 出脚本和分镜，但发布永远人工；Learning Studio 的 AI 建课，但认知评价走结构化规则。AI 是产能，不是裁判。

## 自用驱动

三个项目都解决我自己的问题：家里记账分不清个人和家庭的账，做推文视频一条要两小时，自学不知道到底学会没有。InkFlow 现在每条视频都走它，Aurum 家里在用，Learning Studio 自学在用。

自己当用户有个天然的好处：丑和难用忍不了三天就会改。
